# DeepSeek 人族竞技 Bot

独立实现的 Terran（人族）Bot，入口为 `bots/deepseek/bot.py` 中的 `CompetitiveBot`。
继承 `sc2.bot_ai.BotAI`，可无参数实例化，供统一对局脚本直接加载。

## 入口

```python
from bots.deepseek.bot import CompetitiveBot

# 或
from bots.deepseek import CompetitiveBot
```

- 依赖：`burnysc2==7.3.0`（导入名仍是 `sc2`），Python 3.12。
- 验收环境：SC2 `5.0.17.98745`，地图 `RedCityLE`，人族内战/跨种族均可加载。
- 不联网、不调用外部模型、不读取其他参赛者目录。

## 打法：单兵营双开 → 三兵营生化 + 医疗运输机 + 少量坦克

### 开局时间轴

| 时间/人口 | 动作 |
| --- | --- |
| 13–14 人口 | 补给站 |
| 15 人口 | 兵营 |
| 兵营开工后 | 气矿（1 座） |
| 20 人口 | 第二座补给站 |
| 约 3:20，400 矿 | 自然分矿（单兵营双开） |
| 4:00 左右 | 主基地升级轨道指挥中心，兵营补到 3 座 |
| 3:30–4:00 | 工厂（科技实验室） |
| 5:00 左右 | 星港（反应堆）、工程站 |
| 5:00 起 | 兴奋剂 / 盾牌 / +1 攻防，医疗运输机与坦克 |
| 6:00 起 | 3 兵营持续生化，视兵力主动推进 |

### 经济与恢复

- 农民目标 = 每块矿 2 人 + 每座气矿 3 人（上限 66）；主矿饱和后自动把多余农民调往分矿。
- 空闲农民每 0.4 秒重新分配；气矿始终保持 3 人；矿骡优先投放。
- 被骚扰后农民数低于目标的 55% 时进入 20 秒“经济紧急状态”：优先补农民、暂停扩张和科技建筑。
- 基地失守会记录坐标，90 秒内不再回到该矿点；期间改去更远的扩张点，避免连续送基地。
- 外矿失守时主力回防，威胁解除后按“农民数 + 兵力”重新决定扩张数量。

### 生产与科技

- 兵营：1 号科技实验室（兴奋剂、掠夺者），其余反应堆；至少保证 1 个科技实验室。
- 工厂科技实验室出坦克（上限 3），星港反应堆出医疗运输机（上限 6）。
- 升级顺序：兴奋剂 → 战斗盾牌 → +1 步兵武器 → +1 步兵护甲 → +2/+3。
- 看到成规模敌方空军（≥3 个可攻击空中单位）时转维京，并在各基地补导弹塔。

### 侦察、防守、进攻

- 约 1:35 派 1 个农民去敌方出生点；中后期用轨道扫描补情报。
- 敌方单位进入基地 30 格内即判定威胁；自然矿方向建地堡并装 4 个机枪兵。
- 威胁较大且兵力不足时拉最多 10 个农民协防；农民在敌人贴脸时暂时躲避。
- 兵力 ≥20–26 人口、至少 1 架运输机、家中无威胁时主动推进；优先攻击见过的敌方基地。
- 接敌时优先集火坦克/巨像/潜伏者/毒爆等高价值单位；血量健康的生化单位打兴奋剂。
- 部队减员或明显劣势时撤退重整，兵力恢复后再次推进。

## 客户端断开排查（2026-11-24）

现象：作为客机（player 2）进入本机双客户端对局时，游戏内约 1:46 客户端断开，
SC2 报 `Unknown System Error 480098739`（`ErrorType NON-FATAL`）。

已收集到的证据：

1. 同一局（105.62 秒）里 webgpt 的 `on_step` 是 592 次，本 Bot 是 1183 次 —— 正好 2:1。
   `Client.game_step` 默认 4，`_play_game_ai` 不再改写；本 Bot 旧版在 `on_start` 里写死
   `game_step = 2`，于是本机被推成对手两倍的帧数、两倍的请求量。
2. 崩溃瞬间的客户端截图停在“建造科技实验室 / 选择目标”，与本 Bot 第一次挂附件的时刻重合；
   旧版 `_manage_addons` 每帧都对同一栋兵营重复提交 `BUILD_TECHLAB_*` 放置指令，
   且没有检查附件位是否被占、技能是否真的可用。
3. 四份客户端崩溃日志的 `GameLoop` 各不相同（2366/3205/3506/3833），说明不是某个固定时间点，
   而是“某个操作首次出现”时触发；四次都是客机侧崩溃。

对应修改：

- `on_start` 不再改写推进步长，只在对局脚本给的值不是 4 时打一条 warning。
- 附件改用 `game_data` 里的 `creation_ability` + `building.build(addon)`，下单前用
  `can_place_single` 确认 2x2 附件位可用；位置被占则 10 秒内不再尝试，同一栋建筑
  30 秒内不重复下单。
- 所有每帧下发的指令统一走 `_issue()`：同一单位在 0.6–2 秒内不重复提交同一条指令，
  并统计“指令/帧”写入状态日志。
- 开局/补给/导弹塔的放置尝试都加了 1–2 秒限速，放置失败不再每帧发起放置查询（每次都是 RPC）。

下一场需要盯的日志：状态行里的 `指令=x/帧(峰值n, 去重m) 步长=4`，
以及崩溃前最后一条 `[DeepSeek] 挂载附件 ...` / `附件位被占 ...`。

## 第二轮迭代：从三场复盘定位的两个问题（2026-11-24）

数据来源：`results/round-robin-20261124/`（本轮参赛提交 `32e1b50` 的三场录像与复盘）。

### 问题 1：家里只要出现一个敌人，主力就整局不出门

- 证据（复盘）：`deepseek-vs-antigravity` 4:56–15:21 共 625 秒没有记录到任何敌方单位死亡，
  同期对手在 4:05、9:21 各拆掉我方一座指挥中心（(134,156)、(146,80)）；
  `vs-codex` 4:00–7:25、`16:41–20:42` 同样长时间零击杀。
- 证据（代码）：`_manage_defense` 只要“任意一个能攻击的敌人在基地 30 格内”就置
  `_threat_level >= 1`，随后每帧 `_defense_until = time + 8`（永久续期），
  而 `attack_ready()` 的入口条件是 `threat_level > 0 → return False`。
  于是：**一个死神绕后 = 全军永久待命**；同时 `_manage_structures`、`_manage_expansion`
  也以 `threat_level > 0` 直接 return。
- 属于推断的部分：击杀空窗本身只能定位区间，无法单独证明“军队一直待命”；
  但代码路径是确定的一票否决，且不带任何时长上限。

改动：

- 新增纯函数 `threat_blocks_attack()`：威胁 ≥8 人口，或 ≥5 个单位且我方部队 <15 人口，
  才算“拦阻”。零星骚扰不再拦路。
- `attack_ready()` 的入参由 `threat_level: int` 改为 `threat_blocking: bool`。
- 只有拦阻级威胁才续期 `_defense_until` 并召回家中主力；骚扰级只打日志
  （`骚扰未拦阻推进：敌 x 人口/y 单位 位置=(..)`）、拉农民、补地堡。
- `_manage_structures` / `_manage_expansion` / `_manage_army_production` 改用
  `_threat_blocking`；兵营数为 0 时，即使被正面推进也照建。
- 撤退后 20 秒重整期（`_retreat_at`），避免 ATTACK / RETREAT 反复横跳。

### 问题 2：开局兵营“下了单但没建成”，前 5 分钟 0 兵力 + 1.1–1.7k 矿

- 证据（复盘，`deepseek-vs-codex`）：1:23–3:45 人口上限一直是 31
  = 指挥中心 15 + 两座补给站 8+8，始终没有兵营的 15；同期矿 1140 → 1695，
  人口 19/31（既不缺钱也不缺人口），`minerals_lost` 直到 7:58 都是 0（不是被拆）。
  同类现象：`vs-antigravity` 2:22 矿 1235、6:26 矿 2260 仍然 0 兵力。
- 证据（代码）：开局序列用一次性布尔标记，`build()` 只要返回建筑就置位；之后
  既不校验“建筑是否真的存在”，也不校验“施工进度是否在动”。若 SCV 被击杀或落点
  走不到，标记永久为真，而 `_manage_structures` 又把 `structures()` 的数量当真
  （包含 0% 进度的建筑），于是整局都不会再补兵营。
- 属于推断的部分：具体是“被击杀”还是“落点不可达”无法从现有复盘区分；
  两者都在本次修复覆盖范围内。

改动：

- `_verify_opening_builds()`：兵营下单 15 秒后仍不存在、或存在但 25 秒内进度 ≤1%，
  就重置该步骤并改用 `random_alternative=True` + 更大半径重下；气矿 20 秒未开工同样重试。
- `_usable_structures()`：只统计“已完工或进度 >1%”的建筑，0% 卡死的建筑不再占配额。

### 下一场要看的量化指标

状态行新增：`兵营=n 威胁=<供应>/<单位数> 拦阻=是/否 首推=m:ss 进攻占比=xx%`。

**主指标：6:00–12:00 的 `进攻占比` ≥ 50%**（本轮三场该值约为 0：
要么从未进入 ATTACK，要么进入后立刻被骚扰打断）。辅助指标：`首推` 应 ≤ 7:00，
且 `兵营` 在 2:30 前 ≥ 1。

### 问题 1：产能与科技被自己卡住（人口墙 + 附件墙）

- 证据：两局 6:25.7 都是 68–69/69 人口满（对手 78），8:16 局银行里压着 1,140 矿；
  8:16 局 4 座兵营开战前 0 个附件（整局没有兴奋剂/盾牌、0 个掠夺者），
  8:40 局 3 座兵营只有 1 科技实验室 + 1 反应堆，同期对手是 1 科技实验室 + 4 反应堆。
- 原因：`_manage_supply` 只在剩余 4 人口时补站且最多排 2 座；`_try_addon` 要求
  `building.is_idle`，而兵营几乎一直在训练。
- 改动：补给站按“每座可出兵建筑预留 2 人口（最多 12）”提前补，存款 ≥300 矿时允许排 3 座；
  附件允许在生产队列后面排队（队列 >1 时仍等待），下单被客户端拒绝时退避 10 秒。

### 问题 2：首战姿态（主力贴着分矿指挥中心、防守不打兴奋剂、不优先架起坦克）

- 证据：8:16 局 6:31.2–6:34.2 的 3.0 秒内 14 个陆战队员死在 (44,26)/(44,27)
  （分矿指挥中心 (42,24) 的边角）；8:40 局 6:42.0–6:42.7 的 0.7 秒内 4 个死在同一点 (22,122)。
  两局首战合计 42 个作战单位换 5 个陆战队员；8:40 局 3:50 就有兴奋剂，全局 0 次使用。
  两个首战的攻击指令与接触几乎同时发出（6:27.8 / 6:32.1），不是“没下令”，是部队没展开。
- 改动：新增 `staging_point()`，GATHER 的集结点从分矿指挥中心本体改为朝对手前出 10 格；
  `_defend` 只选地面目标、优先 `HIGH_VALUE_TARGETS`（含架起坦克），接敌 16 格内打兴奋剂。

## 已知弱点 / 待实战验证

1. **未做实机对局验证**：本轮按要求没有启动 SC2，所有验证均为离线测试。
2. **附件位置**：兵营/工厂/星港用 `find_placement` 就近建造，若附件位被补给站挤占，
   科技实验室可能延迟；代码在 420 秒后不再为此阻塞产能，但仍有建造位风险。
3. **不堵口**：没有做main ramp/自然坡的建筑堵口，早期防大量小狗/叉子依赖地堡与农民协防。
4. **坦克微操简化**：只做“防守/接敌架起、长距离移动收起”，没有做架起位置优化与手动集火。
5. **空投/多线**：运输机只用于治疗与跟随，不执行空投骚扰；多线防守靠回防。
6. **对手情报有限**：只根据可见单位与见过的建筑调整，不猜测未侦察到的科技。
7. **主力出门后家里更空**：零星骚扰不再召回主力，若对手用小股部队持续拆迁分矿，
   本版会接受一部分经济损失换取推进；这是有意的取舍，需要用下一场数据确认是否过度。
8. **兴奋剂技能 ID**：使用 `EFFECT_STIM_MARINE` / `EFFECT_STIM_MARAUDER`；
   若客户端拒绝该指令，只会少一层输出，不影响其他逻辑，需要在实战日志中确认。
9. **地图适配**：以扩张点与出生点距离驱动，未针对 RedCityLE 的具体坡道做专门建筑学。
10. **附件排队**：第 7 代允许生产中的建筑把附件排在队列后面。若客户端拒绝该指令，
    代码退避 10 秒后重试（行为退化到“等空闲”），不会回到每帧提交；真实客户端表现未验证。
11. **集结点地形**：10 格前出的集结点没有做可走性判断，若落在不可走区域，部队会绕行；
    需要实战确认是否会被地形卡住。

## 对局约束

- 只使用正常视野内的 `enemy_units` / `enemy_structures`，不读取 `all_enemy_units`。
- 战略目标来自“亲眼见过的敌方建筑”记忆（10 分钟过期），不读取战争迷雾。
- 决策全部本地执行，无网络请求；常规建造用固定候选位置（`random_alternative=False`），
  只有“下单后 15 秒仍未开工”的重试才改用随机候选位，避免在同一个不可达点反复失败。
