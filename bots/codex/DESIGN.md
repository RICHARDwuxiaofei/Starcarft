# Starcarft 人族 Bot 开发版

## 入口

统一对局脚本可从仓库根目录导入 `bots.codex.bot.CompetitiveBot`，也可以按文件加载本目录的 `bot.py`。将无参数创建的 `CompetitiveBot()` 交给人族席位。入口导入和实例化均无启动游戏的副作用。

目标对局为 RedCityLE、SC2 `5.0.17.98745`。本版在任一出生点均使用游戏提供的出生位置、地形和扩张点计算路线与站位。

```powershell
python -m pip install -r bots/codex/requirements.txt
python -B -m unittest bots.codex.test_offline -v
ruff check --no-cache --isolated bots/codex/bot.py bots/codex/test_offline.py
ruff format --check --no-cache --isolated --line-length 110 bots/codex/bot.py bots/codex/test_offline.py
```

## 打法与取舍

- **开局与经济。** 以 SCV、补给站、兵营和第一气矿建立基础产出。先出陆战队，有资源并且基地安全时插一个死神侦察，重工厂接科技实验室和坦克。矿工分矿、气矿补人、轨道指挥部、矿骡和补给都按当前人口、产线和订单更新。主矿开局优先保证矿工数量。基地接战时让防守产出先于升级轨道指挥部，安全后再扩张。
- **施工与恢复。** 常规建筑为加挂件和指挥中心预留地块，避开资源簇并检查放置和工人可达性。补给站完工后降下，减轻路径堵塞。遇到被打断的地基派空闲或采矿 SCV 接手，扩张点遭拒或不可达就冷却并检查下一处。失去最后一座指挥中心后，仍有 SCV 和 400 矿时尝试重建。
- **侦察与防御。** 死神在低血量或接近敌方火力时撤向安全处。敌方建筑记忆来自曾亲眼看到的位置，回访确认空置或见到起飞会清除。基地遇袭时，部队优先回援威胁最集中的区域，受威胁的矿工绕开火力采安全矿或撤离，必要时建地堡并装兵。中期留一发扫描给隐形威胁，也可根据友军近基地内的不明掉血判断是否值得扫一发。
- **部队编成。** 以陆战队、少量掠夺者和攻城坦克为主，医疗运输机治疗生化部队。兵营科技实验室研究兴奋剂和后续升级，工程站研究步兵攻防。观察到有威胁的空军后补维京，有多架空军时让首架维京优先于本轮坦克花气。有空袭或隐形迹象时考虑在矿区补防空塔。
- **出击与再集结。** 默认在集结半径内凑够 14 个生化单位、3 辆坦克和 2 架医疗运输机出门，也允许其他高战力阵容满足阈值后出门。坦克有地面接触和掩护时架设，失去射击机会后收起跟进。后续部队追赶主队。若兵力跌破本轮峰值的 58%、前线局部兵力明显不足，或自家基地告急，则回撤。恢复期满且兵力与队形重新达到门槛后再进攻。经济与生产贯穿三个阶段。

## 离线验证边界

离线用例构造观察帧并使用 `burnysc2==7.3.0` 的真实 `Unit`、`UnitCommand`、造价、人口及订单接口。覆盖入口加载、开局采集至重工厂、补给预判和续建、建筑放置、扩张改选、重建主基地、生产与科研预算、早期防空优先级、反应堆队列、矿工避险、迷雾接触、扫描、坦克架设，以及首攻失败后再推进。测试替身负责地图查询和对局观察，实局指令接受、帧耗时和时序需要在 RedCityLE 核验。

## 已知弱点与实战核验

- 开局以矿工和兵营恢复能力为主，没有专门堵口或工人对砍方案。优先用两侧出生点验证摆位、第一气矿饱和时间、补给衔接，以及基地遭遇早期一波时的矿工损失。
- 主力集中控场，多线骚扰、空投和大范围法术会考验回防与阵型。需要查看坦克架设、解除架设和脱战时实际掉队多少，尤其是坡口和窄路。
- 扫描猜测可能误判，极早隐形、重空军和大规模远程消耗仍是弱点。先确认实局扫描、加挂件、地堡和医疗指令，再通过多局评估侦察、首攻窗口和二次集结的收益。
