## 本轮设计与待验证假设

检查自己的基线实现后，确认了两个机制缺口：`strategy.py` 的损失判断主要比较当前军队人口
与出击时人口的一半，持续生产能掩盖已损失的单位；撤退结束又允许经过 24 秒后绕过归队条件。
这与观测现象相容，但 JSON 不能证明它们是上述每次不利交换的唯一成因。

1. 使用本玩家正常 API 的 `state.score`，跟踪累计军队损失价值及全部击杀价值的 30 秒差分。
   军队损失达到 600 且大于同期击杀收益的 1.8 倍时，触发重整。
   收益计入击杀工人和建筑的价值，避免只因战斗单位交换差而忽略有效经济打击。
   矿物与瓦斯按 1:1 计；己方经济类损失不纳入军事损失。每次新出击重置基线，旧亏损和旧收益不带入。
   只统计起止样本都在窗口内的区间，不按比例猜测边界死亡时间；长观察中断与计数器异常重新建基线。
2. 所有撤退原因都锁定后撤集结点；重整至少保持 12 秒，且至少 70% 的武装单位估算战力进入该点 16 半径内，
   并且没有当前局部兵力劣势，才解除重整。支援单位不单独构成可出击军队；清空军队后回到正常建设状态。
   仍需通过原有出击条件才重新进攻，不通过“等满 24 秒就无条件重进”的时间旁路结束。
   新矿不拖动重整点；锚定基地失去/起飞、点不可通行或一度无基地后恢复落地基地时重新选择。
3. 家防响应优先；临时回防不应抹掉尚未完成的重整义务。

这些阈值是需要实战校验的启发式选择，未由三份 JSON 精确拟合。
共享 JSON 没有每秒完整死亡分数；候选段的损失汇总不能充当 `state.score` 时间序列。
因此不能声称新逻辑必然会在上述比赛某个具体秒数触发，也不能把这些资料当成实际代码重放。
有关自己的行为实现见 [strategy.py](strategy.py) 和 [bot.py](bot.py)。

`CompetitiveBot` 的导入路径和构造参数不变，版本标记为 `1.1.0`。
运营、兵种配比、建造顺序、侦察与单兵微操本轮没有改动。
撤退继续使用原战斗控制的合法移动/坦克收起指令，不引入新技能或对手定制规则。

## 解释与验证边界

- 候选交战段是归因损失的启发式聚类；时间可重叠，也可能覆盖多处分散交战。
- `first_losses` 只列各段最初若干损失，不能外推全段击杀来源比例。
- 总损失列表中的 MULE 包含自然到期，不应并入战斗损失判断。
- JSON 不能证明部队一路散送、具体指令频率、缺少侦察，或完全没有执行后撤。
- 使用本玩家正常分数与观测，不读取对手进程、隐藏状态或对手实现。
- 交换分数是本玩家全图汇总，远处击杀收益可能掩盖前线不利交换；本轮没有做战场归属统计。
- 取消超时绕过会延长某些撤退；锁点只检查格子可通行性，不验证完整路线。
  少数卡路单位可由 70% 比例容忍，但大量部队卡路仍可能拖延重整，需由实战确认。
- 代码审查与离线测试可以验证状态转移和指令行为，无法证明新版本的实战强度。

## 下一轮实战最值得核对的指标

统一地图、客户端和平衡版本、时间限制与对手条件，对比 `b301d0b` 与本分支，并交换出生位置、进行多局。

- 记录 30 秒、60 秒窗口内的军队损失与全部击杀收益，检查不利交换是否减少。
- 记录每次重整触发的游戏时间、两项差分和触发次数；结合录像核对是否确实接战受阻。
- 记录重新进攻时的归队战斗力量比例及重整耗时，检查援军未到齐时是否仍持续接敌。
- 记录误撤：有利交换、工人/建筑击杀收益较高或正在完成突破时是否被不必要地打断。
- 记录重整是否因卡路拖延，尤其是超过 24 秒还未恢复的情况；结合锁定点、归队率和实际位置判断。
- 核对遭遇家防威胁时是否及时响应、解除后是否合理完成重整；同时比较结束时长与最终胜负。

### 新增遥测如何核对

裁判可沿用 `CompetitiveBot(seed=..., telemetry_path=本方独立路径)`；缺省路径不会写日志。
现有 `stance` 状态转换与每 10 游戏秒 `snapshot` 都包含 `engagement`：

| 字段 | 含义 |
| --- | --- |
| `trade_available`、`trade_seconds` | 分数接口可读取、实际统计跨度；不是完整 30 秒时不外推 |
| `army_loss`、`enemy_gain`、`bad_trade` | 当前窗口资源损失、收益与门槛判断，不代表已触发撤退 |
| `bad_trade_retreats`、`last_bad_trade` | 已触发次数，以及最近一次的游戏时间、损失、收益和统计跨度 |
| `regroup_active`、`regroup_point` | 是否仍有重整义务及当前锁定位置；回防时义务也可为真 |
| `regroup_seconds`、`regroup_fraction` | 自触发以来的游戏秒数（含回防时间）、到点武装战力比例 |

字段记录最近一次战略更新，默认间隔 0.7 游戏秒；快照默认每 10 秒，不能冒充逐秒完整轨迹。
要评价上述 60 秒窗口或局部损失，仍需中立回放解析或裁判补充采样。

旧版的三场胜局仅作为发现问题的依据；新版本是否改善以上指标，等待用户统一安排实战。
