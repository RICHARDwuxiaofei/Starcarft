## 测试与实际游戏的边界

共有八个测试文件，既有纯决策测试，也有真实库对象的集成测试。
其中12个完整流程用例使用：

`SC2 protobuf → GameData/GameState → BotAI._prepare_step → Unit/Units → Bot.on_step → UnitCommand`

这些测试中的客户端 RPC 被 `OfflineClient` 替代，单位数据、价格和地图是合成夹具。
它们能发现接口拼错、对象类型不匹配、指令覆盖和运营优先级错误，**不能证明游戏引擎会接受每个真实落点，
也不能证明真实对局的胜负、寻路效果、平衡数值或战术强度**。

## 覆盖的关键风险

| 类别 | 测试内容 |
| --- | --- |
| 资源与指令 | 多个兵营不能重复花同一份50矿；人口预留；反应堆第二订单显式排队；不排第三个；治疗/变形不被移动覆盖 |
| 公平信息 | snapshot不刷新记忆；未揭露的隐形单位不被精确攻击；过期与确认消失的建筑记忆清理 |
| 战略 | 单农民侦察不会全军回防；前置建筑和rush触发响应；进退迟滞；未知敌情时继续主动搜索 |
| 微操 | 技能条件、真实射程、坦克最小射程、架收迟滞、医疗运输机治疗分摊、空军避险、维京收尾、危险范围 |
| 建造恢复 | 墙位堵塞时补给回退；附件技能可用但落点堵塞仍会搬迁；被打断施工可接手 |
| 经济重建 | 0基地、1SCV、400矿、0人口上限时完整决策只下达指挥中心建造，不先把钱花到补给或兵营 |
| 边界状态 | 全无单位；12/13工人上限的开局补给；建筑pending不重复计数；建造工人不被采矿逻辑抢走 |
| 结果真实性 | 未决结果、互相冲突的胜负、脚本错误、中断、无回放、平局分别记录，不伪造获胜或回放 |
| Windows中文输出 | 在强制cp1252管道环境下正确输出中文帮助/错误信息；StringIO捕获流不被替换或关闭 |

上述测试暴露的问题已修复，并保留回归用例。首次GitHub Windows检查发现中文帮助在默认管道编码下
可能触发UnicodeEncodeError；启动器现在在参数解析前统一支持重配置的stdout/stderr为UTF-8，
并新增3个回归用例。后续两套平台检查以该分支最新提交的Actions结果为准。

## 后续实战验收

用户允许使用电脑后，应先确认SC2客户端能够初始化图形与API，再运行：

1. 对内置电脑的一场短局，确认地图、实际建造、科技、作战和回放都正常。
2. 镜像实时局，观察两份客户端负载与持续运营。
3. 由中立裁判加载双方选定提交，固定游戏/平衡版本与地图哈希，记录多个种子并核对/交换出生点。
4. 根据回放检查卡人口、资源浮动、进攻衔接、反隐、支援机损失与晚期收尾，再调整启发式阈值。

本次没有启动SC2、操作用户两台电脑、读取mizuki实现，或把Bot合并到主分支。
主分支只有用户要求的公共 `AGENTS.md` 规则变更。
