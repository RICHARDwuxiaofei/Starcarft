## 优先级 1：为什么二矿建到一半停了几分钟

- 两场对 AGY，Mizuki 的第一座扩张指挥中心都开在 **(19,134)**。第 7 代 **2:01** 开工、**7:45** 被摧毁，中间没有完工记录。第 8 代同一建筑单位编号 **2:03** 开工、**8:00** 完工、**9:20** 被摧毁。
- 第 8 代对 AGY，约 **3:56、5:00、6:26、7:30** 四个采样点一直是 **21 名活跃工人**。AGY 二矿 **3:06** 完工，**6:26** 有 **50 名活跃工人**。活跃工人是录像采样指标，请区分存活 SCV 数、正在采集的 SCV 数和当前分配。
- 第 8 代对 DeepSeek，二矿同样约 **2:03** 开工、**3:14** 完工；**6:26** 有 **45 名活跃工人**。请先把这条正常路径保留下来，比较两种局面中建筑工人被敌方驱离、死亡、撤离或重新分配后，未完工建筑有没有重新分配工人。
- 建筑时间轴证明施工长期未完成，单凭回放统计无法确认是工人被撤离、续建条件没满足、指令被覆盖，还是另一项状态机问题。请结合回放画面、单位编号和自己的代码逐项核对。标出第一次中断及恢复的时间、当时能看到的威胁、原建筑工人和替补工人的状态。

确定原因后再改。若是续建逻辑遗漏，请覆盖「建造者阵亡」「建造者撤离但威胁仍在」「威胁解除后恢复」「已经有工人续建时避免重复派工」「原建筑已毁时释放任务」。恢复必须由合法可见信息触发，保留第 8 代的安全撤离行为。
